# FR-03: Product Search

**Branch:** `feature/FR-03`

## Overview

This feature adds search by product name. Search input is debounced, so the API is called only after the user stops typing for 500 milliseconds rather than on every keystroke. Search results use the same pagination as the product list, so infinite scroll continues to work while searching.

## Implementation

### 1. Endpoint

A new endpoint is added for searching products:

```dart
static const String productsSearch = '/products/search';
```

### 2. Repository Interface

`ProductRepository` declares a new method for searching:

```dart
Future<ProductsResponse> searchProducts({
  required String query,
  required int limit,
  required int skip,
});
```

The `limit` and `skip` parameters match the existing list request, which allows search results to be paginated in the same way.

### 3. Repository Implementation

The implementing class must provide every method declared in `ProductRepository`, so `searchProducts` is implemented and calls the API through the API client:

```dart
@override
Future<ProductsResponse> searchProducts({
  required String query,
  required int limit,
  required int skip,
}) {
  return _apiClient.get<ProductsResponse>(
    ApiEndpoint.productsSearch,
    queryParameters: {
      'q': query,
      'limit': limit,
      'skip': skip,
    },
    parser: (data) => ProductsResponse.fromJson(data as Map<String, dynamic>),
  );
}
```

The search text is sent as the `q` query parameter, and the response is parsed into `ProductsResponse`.

### 4. Debounce

The provider defines the debounce delay:

```dart
static const Duration _debounceDuration = Duration(milliseconds: 500);
```

Each change to the search text restarts the delay. The request is sent only when the user pauses typing for 500 milliseconds, which reduces unnecessary API calls and avoids flickering results.

### 5. Request Method

A single `_request` method decides which API call to make:

```dart
Future<ProductsResponse> _request(int skip) {
  if (_query.isEmpty) {
    return _productRepository.fetchProducts(limit: _limit, skip: skip);
  }
  return _productRepository.searchProducts(
    query: _query,
    limit: _limit,
    skip: skip,
  );
}
```

When the search text is empty, the normal product list is fetched. Otherwise, the search endpoint is used. Both the initial load and `loadMore()` go through this method, so pagination behaves the same in both modes.

## Data Flow

1. The user types in the search field.
2. The provider waits 500 milliseconds after the last change.
3. `_request` checks the query and calls either `fetchProducts` or `searchProducts`.
4. The repository calls the API and returns a `ProductsResponse`.
5. The provider updates the list and the screen displays the results.

## Benefits

- **Fewer API calls:** debounce sends one request per pause in typing instead of one per keystroke.
- **Single request path:** `_request` keeps list and search logic in one place, so pagination is reused.
- **Clean fallback:** clearing the search returns to the full product list without extra handling.
- **Consistent architecture:** search follows the same endpoint, repository and provider layers as the existing list.
