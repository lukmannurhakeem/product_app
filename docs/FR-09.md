# FR-09: Recent Searches

**Branch:** `feature/FR-09`

## Overview

This feature remembers the user's recent search queries and shows them as a list when the search field is focused. Tapping a recent search runs it again, and the user can clear the whole history. It extends the search feature from FR-03.

## Implementation

### 1. Recent Search Provider

A new `RecentSearchProvider` manages the list of recent queries. It reads and writes the history through `RecentSearchStorage` and notifies the UI when the list changes.

### 2. Service Locator

The provider is registered in the locator as a lazy singleton for dependency injection:

```dart
locator.registerLazySingleton<RecentSearchProvider>(
  () => RecentSearchProvider(locator<RecentSearchStorage>()),
);
```

Registering it in the locator lets any screen use the same instance, so the history stays consistent across the app.

### 3. Recent Searches UI

The recent searches list was enhanced using Claude Code. It shows a header with a clear button, followed by one tile per recent query:

```dart
// TextFieldTapRegion stops taps here from counting as "outside" the
// search field, which would unfocus it before onTap fires.
return TextFieldTapRegion(
  child: ListView(
    children: [
      Padding(
        padding: const EdgeInsets.only(left: 16, right: 8),
        child: Row(
          children: [
            Expanded(
              child: Text(
                l10n.recentSearches,
                style: context.topology.textTheme.titleSmall,
              ),
            ),
            TextButton(
              onPressed: context.read<RecentSearchProvider>().clear,
              child: Text(l10n.clearRecentSearches),
            ),
          ],
        ),
      ),
      for (final query in items)
        ListTile(
          dense: true,
          leading: const Icon(Icons.history),
          title: Text(query, maxLines: 1, overflow: TextOverflow.ellipsis),
          onTap: () => onSelected(query),
        ),
    ],
  ),
);
```

Key points:

- **`TextFieldTapRegion`:** taps inside this region are not treated as "outside" the search field. Without it, tapping a suggestion would unfocus the field before `onTap` fires and the selection would be lost.
- **Header:** the title and a clear button are shown in one row. The clear button calls `clear` on `RecentSearchProvider`.
- **Recent items:** each query is a `ListTile` with a history icon. The text is limited to one line with an ellipsis, so long queries do not break the layout.
- **Selection:** tapping an item calls `onSelected(query)`, which runs that search.
- **Localisation:** labels use `l10n`, so the text follows the app language.

### 4. Watching the Provider

The search UI watches `RecentSearchProvider` to decide what to display. When there are recent searches, the list is shown, and when the user taps clear, the provider empties the list and the UI updates automatically.

## Data Flow

1. The user focuses the search field.
2. The UI watches `RecentSearchProvider` and shows the recent searches.
3. The user taps a recent search, and `onSelected(query)` runs the search.
4. Alternatively, the user taps clear, and the provider clears the history and notifies listeners.
5. The UI rebuilds without the cleared items.

## Benefits

- **Faster searching:** users can repeat a previous search with one tap.
- **User control:** the history can be cleared at any time.
- **Reliable interaction:** `TextFieldTapRegion` prevents the field from losing focus before a tap is handled.
- **Shared state:** a single provider instance keeps the history consistent across the app.
- **Localised:** all labels come from `l10n`.
