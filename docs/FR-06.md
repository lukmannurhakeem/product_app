# FR-06: Offline Fallback

**Branch:** `feature/FR-06`

## Overview

This feature lets the product list work without a connection. The first page of products is cached each time it is fetched from the API. When the device is offline and there is nothing on screen, the provider falls back to the cached products and the screen tells the user they are viewing offline data.

## Implementation

### 1. Storage Key

A new key is added to the local storage keys for the product cache:

```dart
static const products = 'products_cache';
```

### 2. Product Storage

`ProductStorage` (`lib/storage/product_storage.dart`) manages reading and writing the cache. It wraps `LocalStorageService`, so the rest of the app does not deal with storage keys or serialisation directly.

### 3. Service Locator

The locator is updated, using Claude Code, to register `ProductStorage` as a lazy singleton that receives `LocalStorageService`:

```dart
locator.registerLazySingleton<ProductStorage>(
  () => ProductStorage(locator<LocalStorageService>()),
);
```

### 4. Writing the Cache

`ProductsImpl` now receives `ProductStorage` through its constructor, in addition to `ApiClient`:

```dart
class ProductsImpl implements ProductRepository {
  final ApiClient _apiClient;
  final ProductStorage _productStorage;

  ProductsImpl(this._apiClient, this._productStorage);
```

The cache is written when the API is hit:

```dart
if (skip == 0) unawaited(_productStorage.write(response));
return response;
```

- **First page only:** the cache is written only when `skip == 0`, so it always holds the first page of the list.
- **Non-blocking:** the write is not awaited, so saving the cache never delays the response shown to the user.

### 5. Using the Cache in the Provider

When a request fails, the provider checks whether it can fall back to the cache:

```dart
final error = ErrorHandler.handle(e, st);
final cached = error is NetworkException &&
        _query.isEmpty &&
        _products.isEmpty
    ? _productRepository.getCachedProducts()
    : null;

if (cached != null && cached.products.isNotEmpty) {
  _products = cached.products;
  _isOffline = true;
  _hasMore = false;
} else {
  _error = error;
  if (_products.isNotEmpty) {
    SnackbarService.showError(e, stackTrace: st);
  }
}
```

The cache is used only when all of the following are true:

- The error is a `NetworkException` (the device is offline).
- The search query is empty, because only the main list is cached.
- No products are currently loaded.

When the cache is used, `_isOffline` is set to `true` and `_hasMore` to `false`, so infinite scroll does not try to request more pages. If there is no usable cache, the error is stored and `_ErrorView` is shown. If products are already on screen, a snackbar reports the error instead and the list is kept.

### 6. Product Screen

The product screen shows an offline notice at the top of the list when the provider is in offline mode:

```dart
if (provider.isOffline) const _OfflineNotice(),
```

Images are displayed with `CachedNetworkImage`, so product images that were loaded previously are served from the image cache and remain visible offline:

```dart
return CachedNetworkImage(
  imageUrl: imageUrl,
  ...
);
```

## Data Flow

1. The provider requests products and the API call fails with a `NetworkException`.
2. The provider checks that the query is empty and no products are loaded.
3. It reads the cached response through the repository.
4. If the cache has products, the list, offline flag and pagination state are updated.
5. The screen shows the cached products with the offline notice and cached images.

## Benefits

- **Works offline:** users can still browse the product list without a connection.
- **Transparent to the user:** the offline notice makes clear that the data may not be current.
- **No added latency:** the cache write is not awaited, so online performance is unchanged.
- **Safe fallback:** the cache is used only for the unfiltered list when nothing is loaded, and other failures still show the error state.
- **Clear separation:** caching lives in `ProductStorage`, so the provider and screen do not handle storage details.
