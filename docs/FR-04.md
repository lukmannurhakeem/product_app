# FR-04: Product Detail Page

**Branch:** `feature/FR-04`

## Overview

This feature adds a product detail page. When the user taps a product in the list, the app navigates to a new `ProductDetailsScreen` and passes the selected `Product` model as a route argument. The detail screen reads the product directly from the arguments, so no additional API call is needed to display it.

## Implementation

### 1. Route Name

A new route name is added to the navigation routes:

```dart
static const String productDetailsScreen = '/productDetailsScreen';
```

### 2. Route Registration

The route is registered in the navigation route generator, following the same pattern as the existing screens (for example, `wishlistScreen`):

```dart
case productDetailsScreen:
  return (_) => const ProductDetailsScreen();
```

### 3. Product Details Screen

A new `ProductDetailsScreen` is created to display the details of a single product. It receives the `Product` model from the product list screen through the route arguments.

### 4. Resolving the Product

The screen resolves the product with a helper method. It uses the product passed to the widget if one is provided, and otherwise reads it from the route arguments:

```dart
Product? _resolveProduct(BuildContext context) {
  if (widget.product != null) return widget.product;
  final args = ModalRoute.of(context)?.settings.arguments;
  return args is Product ? args : null;
}
```

The `args is Product` check ensures the arguments are of the expected type. If they are not, the method returns `null` instead of throwing an error.

### 5. Navigation

When the user taps a product in the list, the app navigates to the detail screen and passes the `Product` as an argument:

```dart
onTap: () {
  locator<NavigationService>().navigateTo(
    NavigationRoutes.productDetailsScreen,
    arguments: product,
  );
},
```

Navigation goes through `NavigationService`, resolved from the service locator, so screens do not depend on `Navigator` directly.

## Data Flow

1. The user taps a product on the product screen.
2. `NavigationService` navigates to `productDetailsScreen` with the `Product` as an argument.
3. `ProductDetailsScreen` resolves the product from the route arguments.
4. The screen displays the product details.

## Benefits

- **No extra request:** the product is already loaded, so the detail page opens instantly.
- **Centralised navigation:** routes and navigation are managed in one place through `NavigationService`.
- **Type-safe arguments:** the `is Product` check prevents runtime errors from wrong or missing arguments.
- **Flexible screen:** the product can be supplied through the constructor or the route, which makes the screen easy to reuse and test.
