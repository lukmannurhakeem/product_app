# FR-07: Favourites

**Branch:** `feature/FR-07`

## Overview

This feature lets users mark products as favourites. Favourites are saved in local storage, so they persist between app sessions. A single `FavouriteProvider` is registered in the service locator and shared across screens, and a reusable `FavouriteButton` widget is used on both the product screen and the product details screen, so the favourite state is always consistent.

## Implementation

### 1. Storage Key

A new key is added to the local storage keys:

```dart
static const favourites = 'favourites';
```

### 2. Storage Layer

Favourites follow the same pattern used for the product cache in FR-06. The repository implementation reads from the storage class:

```dart
@override
ProductsResponse? getCachedProducts() => _productStorage.read();
```

The storage class wraps `LocalStorageService`, which is passed in through its constructor:

```dart
class ProductStorage {
  ProductStorage(this._storage);
```

`FavouriteStorage` is built the same way and uses the `favourites` key. This keeps storage keys and serialisation inside the storage class, so the provider only deals with favourite data.

### 3. Favourite Provider

A new `FavouriteProvider` manages the favourite state. It reads the saved favourites from `FavouriteStorage`, exposes them to the UI, adds or removes a product when toggled, writes the result back to storage and calls `notifyListeners()`.

### 4. Service Locator

The provider is registered in the locator as a lazy singleton:

```dart
locator.registerLazySingleton<FavouriteProvider>(
  () => FavouriteProvider(locator<FavouriteStorage>()),
);
```

Registering it in the locator allows the same instance to be shared across screens. A change made on one screen, such as the product details screen, is immediately reflected on the others, without passing state between them.

### 5. Reusable Widget

A reusable widget displays and toggles the favourite state of a product:

```dart
class FavouriteButton extends StatelessWidget
```

It listens to `FavouriteProvider` and shows whether the product is currently a favourite. Tapping it toggles the state. The same widget is used on both the product screen and the product details screen, so the behaviour and appearance are defined in one place.

## Data Flow

1. The user taps `FavouriteButton` on a product.
2. The widget calls the toggle method on `FavouriteProvider`.
3. The provider updates its favourites and writes them through `FavouriteStorage`.
4. The provider calls `notifyListeners()`.
5. Every `FavouriteButton` for that product, on any screen, rebuilds with the new state.

## Benefits

- **Persistent:** favourites are stored locally and survive app restarts.
- **Shared state:** a single provider instance keeps all screens in sync.
- **Reusable UI:** one `FavouriteButton` is used on both screens, which avoids duplicated logic.
- **Consistent architecture:** storage, provider and widget follow the same layering as the rest of the app.
