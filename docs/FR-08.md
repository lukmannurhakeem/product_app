# FR-08: Wishlist Screen

**Branch:** `feature/FR-08`

## Overview

This feature extends FR-07 (Favourites). Products marked as favourites are displayed together on a new wishlist screen. The screen reads its data from the shared `FavouriteProvider`, so it updates automatically whenever a product is favourited or unfavourited anywhere in the app.

## Implementation

### 1. Route Name

A new route name is added to the navigation routes:

```dart
static const String wishlistScreen = '/wishlistScreen';
```

### 2. Route Registration

The route is registered in the navigation route generator:

```dart
case wishlistScreen:
  return (_) => const WishlistScreen();
```

### 3. Wishlist Screen

`WishlistScreen` watches the favourite items from the shared provider:

```dart
final items = context.watch<FavouriteProvider>().items;
```

`context.watch` subscribes the screen to the provider, so it rebuilds on every `notifyListeners()` call. When a product is favourited or unfavourited, the wishlist reflects the change immediately.

### 4. Toggle in the Provider

The provider's `toggle` method adds or removes a product and notifies listeners:

```dart
void toggle(Product product) {
  if (_items.remove(product.id) == null) {
    _items[product.id] = product;
  }
  notifyListeners();
  unawaited(_storage.write(_items.values.toList()));
}
```

- **Add or remove in one step:** `_items` is keyed by product id. `remove` returns `null` when the product is not in the map, which means it was not a favourite, so it is added. Otherwise it has just been removed.
- **Immediate UI update:** `notifyListeners()` is called before the write, so the UI responds without waiting for storage.
- **Non-blocking persistence:** the updated list is written to local storage without being awaited, so saving never delays the interaction.

## Data Flow

1. The user taps `FavouriteButton` on the product screen or product details screen.
2. `FavouriteProvider.toggle` updates `_items` and calls `notifyListeners()`.
3. `WishlistScreen`, which watches the provider, rebuilds with the updated items.
4. The updated favourites are written to local storage in the background.

## Benefits

- **Always in sync:** the wishlist updates from the same provider as the favourite buttons, with no manual refresh.
- **Responsive:** the UI updates before the storage write completes.
- **Persistent:** favourites are saved locally and remain after the app is restarted.
- **Low complexity:** the id-keyed map makes toggling a single operation and prevents duplicate entries.
