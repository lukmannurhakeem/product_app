# FR-02: Infinite Scroll

**Branch:** `feature/FR-02`

## Overview

This feature adds infinite scroll to the product list. Products are loaded in pages of **20 items**, and the next page is fetched automatically as the user scrolls towards the bottom of the list. This avoids loading the full catalogue at once and keeps the initial load fast.

## Implementation

### 1. Pagination State

The provider tracks pagination with two fields:

```dart
bool _hasMore = true;
int _fetchIncrement = 0;
```

- **`_hasMore`** indicates whether the API has more products to return. When a fetch returns fewer items than the page size, it is set to `false` and no further requests are made.
- **`_fetchIncrement`** is kept in sync with the current total number of products in the list. It is used as the offset for the next request, so each fetch continues from where the previous one ended.

### 2. Scroll Detection

The product screen listens to the scroll position and triggers loading shortly before the user reaches the end of the list:

```dart
void _onScroll() {
  if (!_scrollController.hasClients) return;
  final position = _scrollController.position;
  if (position.pixels >= position.maxScrollExtent - 200) {
    widget.onLoadMore();
  }
}
```

The check uses the scroll pixel position. When the user is within 200 pixels of the bottom, `onLoadMore()` is called, so the next page is usually ready before the user reaches the end.

### 3. Load More

The `loadMore()` function in the provider fetches the next page from the repository, using `_fetchIncrement` as the offset. It does nothing if `_hasMore` is `false`.

### 4. Merging Results

The new items are combined with the existing list into one list in the provider:

```dart
_products = [..._products, ...newItems];
```

This preserves the products already loaded and appends the new page, then the provider notifies the UI.

### 5. Product Screen

The product screen displays the combined list. As new items are appended, the list grows without resetting the scroll position.

## Data Flow

1. The user scrolls within 200 pixels of the bottom of the list.
2. `_onScroll()` calls `onLoadMore()`.
3. The provider's `loadMore()` requests the next 20 items using `_fetchIncrement`.
4. New items are merged into `_products`, and `_hasMore` and `_fetchIncrement` are updated.
5. The screen rebuilds and displays the extended list.

## Benefits

- **Performance:** only 20 items are loaded at a time, reducing initial load time and memory use.
- **Smooth experience:** the 200 pixel threshold prefetches the next page before the user reaches the end.
- **Efficient requests:** `_hasMore` stops unnecessary API calls once all products are loaded.
- **Correct pagination:** `_fetchIncrement` stays aligned with the loaded total, so no items are skipped or duplicated.
