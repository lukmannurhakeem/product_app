# FR-05: Loading, Empty and Error States; Pull to Refresh

**Branch:** `feature/FR-05`

## Overview

This feature adds clear feedback for every state of the product list: loading, empty, error and offline. It also adds pull to refresh so the user can reload the list manually. Together these make sure the screen always shows something meaningful instead of a blank view or a silent failure.

## Implementation

### 1. Error Handling

An `errors/` module maps network failures to application exceptions. When the device has no connection, the Dio exception is converted into a `NetworkException`; anything else becomes an `UnknownException`:

```dart
DioExceptionType.connectionError => const NetworkException(),
DioExceptionType.unknown => inner is SocketException
    ? const NetworkException()
    : const UnknownException(),
```

This lets the UI distinguish an offline state from other failures without depending on Dio.

### 2. Empty State

`_EmptyView` is shown when the request succeeds but there are no products to display, for example when a search returns no results.

### 3. Error State

`_ErrorView` is shown when loading fails. It checks whether the failure is an offline error and, if so, displays a no internet animation with an icon fallback:

```dart
if (_isOffline)
  Lottie.asset(
    'assets/lottie/no_internet.lottie',
    width: 220,
    height: 220,
    repeat: true,
    errorBuilder: (_, __, ___) =>
        const Icon(Icons.wifi_off, size: 96),
  ),
```

If the animation cannot be loaded, `errorBuilder` shows a `Icons.wifi_off` icon instead, so the offline state is always visible.

### 4. Loading State

The provider exposes two flags for loading:

```dart
bool get isLoading => _isLoading;

bool get isLoadingMore => _isLoadingMore;
```

- **`isLoading`** is used for the initial load, when the screen has no data yet.
- **`isLoadingMore`** is used while the next page is being fetched, so the list can show a loading indicator at the bottom without replacing existing items.

### 5. Provider Updates

Each data method sets the loading flag to `true` at the start of the `try` block and calls `notifyListeners()`, so the UI updates immediately. The `finally` block resets the flag and notifies again. `loadMore()` shows the full pattern:

```dart
Future<void> loadMore() async {
  if (_isLoading || _isLoadingMore || !_hasMore) return;

  final increment = _fetchIncrement;
  _isLoadingMore = true;
  notifyListeners();

  try {
    final model = await _request(_products.length);
    if (increment != _fetchIncrement) return;

    final existingIds = _products.map((p) => p.id).toSet();
    final newItems = model.products.where((p) => !existingIds.contains(p.id));
    _products = [..._products, ...newItems];

    _hasMore = model.products.isNotEmpty && _products.length < model.total;
  } catch (e, st) {
    if (increment != _fetchIncrement) return;
    SnackbarService.showError(e, stackTrace: st);
  } finally {
    if (increment == _fetchIncrement) {
      _isLoadingMore = false;
      notifyListeners();
    }
  }
}
```

Key points:

- **Guard clause:** the method returns early if a load is already running or there is nothing more to load, which prevents duplicate requests.
- **Stale response protection:** `_fetchIncrement` is captured before the request and compared afterwards. If the list was reset in the meantime (for example by a new search or a refresh), the old response is ignored.
- **Duplicate protection:** new items are filtered by `id` before being appended, so the same product never appears twice.
- **End of list:** `_hasMore` becomes `false` when a response is empty or when the loaded count reaches the server total.
- **Error feedback:** failures are reported through `SnackbarService.showError`, so a failed page load does not remove the products already shown.

### 6. Pull to Refresh

Pulling down on the list reloads it from the first page. The refresh resets the list and pagination state, then fetches again, and the stale response guard ensures any request still in flight is discarded.

## Data Flow

1. The provider sets the loading flag and calls `notifyListeners()`.
2. The request runs through the repository and API client.
3. On success, the list is updated. If it is empty, `_EmptyView` is shown.
4. On failure, the exception is mapped by the `errors/` module and `_ErrorView` is shown, with the offline animation for `NetworkException`.
5. The provider resets the loading flag and notifies the UI.

## Benefits

- **Clear feedback:** the user always sees loading, empty, error or offline status instead of a blank screen.
- **Offline awareness:** network failures are identified and shown with a dedicated view.
- **Safe pagination:** guards against duplicate requests, stale responses and duplicate items.
- **Resilient UI:** a failed page load keeps the existing products on screen.
- **Manual recovery:** pull to refresh lets the user retry without leaving the screen.
